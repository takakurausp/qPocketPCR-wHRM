# Environmental DNA Quantitative PCR with qPocketPCR — Workflow

This is a series of workflows that process the raw data `DATA.TXT` obtained with
[`qPocketPCR`](https://gaudi.ch/PocketPCR/) (GaudiLabs, https://gaudi.ch/PocketPCR/)
and perform **environmental DNA (eDNA) quantification**.

Because detection uses a single channel (Cyber Green / SYBR Green), the **target region**
and the **standard amplicon** must be placed in **separate wells**. The target uses a
region that is "slightly broader than the detection range," and it is run in the same well
every time (see below).

## Directory Structure

```
ecDNA_qpcr/
├── scripts/
│   ├── qpcr_core.py            # Core processing library (parsing, baseline, Ct detection, regression)
│   ├── make_synthetic_data.py  # Synthetic DATA.TXT generator (for verification)
│   ├── make_calibration.py     # Generates calibration file (JSON) from a dilution series
│   └── run_qpcr.py             # Workflow integration script (execution entry point)
├── config.json                 # Channel layout and role mapping
├── config_sample.json          # Template for two unknown samples
├── calibration_*.json          # Calibration files (generated by make_calibration.py)
├── data/
│   └── DATA.TXT                # Raw data extracted from qPocketPCR (or synthetic)
└── output/                     # Results (results.tsv, report.md, *.png)
```

## qPocketPCR Raw Data Format

The device writes `DATA.TXT` (`DATAQPCR.TXT`) as a USB Mass Storage drive. The firmware
v1.2+ format is CSV (also auto-detects the older format without a temperature column):

```
Protocol name: <protocol name>       <- first line (optional)
Cycle, Time, Temp, Sensor1, Sensor2, ..., Sensor8
1, 12, 95.2, 1523.4, 1480.1, ...
```

- **Cycle**: PCR cycle (integer). If multiple captures occur within one cycle, the same value repeats.
- **Time**: Seconds since measurement start.
- **Temp**: Measured block temperature at capture time in °C (v1.2+; required for melting/HRM analysis).
- **Sensor1–8**: Fluorescence values for the 8 wells (wellFactor-corrected).

### Amplification → Melting (HRM) in a single run, with automatic separation

After amplification, running a melting ramp (`MELT FROM/TO/INC/HOLD`, e.g. 65→95 °C in
0.2 °C steps) appends a **melting block** to the end of the qPCR section (Cycle stays 1,
but the measured temperature rises monotonically). This script automatically detects that
trailing block and separates it into:

- **qPCR section** → conventional Ct / standard-curve quantification
- **Melting section** → melting curve and Tm (dF/dT peak)

The detection rule is: a boundary where the cycle returns from 2+ to 1, plus a monotonically
rising ramp, plus enough points/temperature span. For files with **melting only**, qPCR
analysis is skipped and only Tm is output.

The device images each well's fluorescence from the side with a camera, applies baseline
and inter-well correction (wellFactor), and then writes this CSV. Because detection uses a
single channel, multiplexing is not possible; targets and standards go in separate wells.

## Workflow Overview

1. **Parse DATA.TXT** — split into `Curve` (cycle seconds vs. fluorescence values) per channel
2. **Role mapping** — specify standard / sample / ntc in `config.json`
3. **Adaptive baseline subtraction and normalization (ΔRn)** — auto-detected before amplification starts
4. **Ct/Cq detection** — fixed threshold method (ΔRn); fallback to maximum-derivative method
5. **Standard-curve regression and PCR efficiency calculation** — linear regression of `log10(quantity)` vs Ct
6. **Quantify unknown samples** — substitute Ct into the regression equation
7. **Output results** — TSV / Markdown report + amplification curve plot & standard curve plot

## Usage

### (A) Run with real device data

Place the file extracted from the device at `data/DATA.TXT`, edit the role mapping in
`config.json` to match your actual well layout, then:

```bash
python3 scripts/run_qpcr.py --data data/DATA.TXT --config config.json --out-dir output/
```

### (B) Verify with synthetic data (works without a device)

```bash
# Generate synthetic DATA.TXT (6-stage standard dilution + 2 samples)
python3 scripts/make_synthetic_data.py --out data/DATA.TXT --seed 1

# Run workflow (old format, amplification only)
python3 scripts/run_qpcr.py --data data/DATA.TXT --config config.json --out-dir output/

# ── Amplification → Melting (HRM) verification ──
# Generate device-format (with Temp column): 45 qPCR lines + 151 melting lines (65→95 °C / 0.2 °C steps)
#   The true Tm of each well is ch0=82.0 °C plus +0.5 °C increments (--melt-tm-base to change)
python3 scripts/make_synthetic_data.py --with-melt --out data/DATA_HRM.txt --seed 1
python3 scripts/run_qpcr.py --data data/DATA_HRM.txt --config config.json --out-dir output_hrm/
# → results.tsv gets qPCR quantification + each well's Tm (within ~±0.5 °C of the true value)

# ── Melting-only run verification (0 amplification cycles) ──
python3 scripts/make_synthetic_data.py --with-melt --n-cycles 0 --out data/DATA_MELT.txt --seed 2
python3 scripts/run_qpcr.py --data data/DATA_MELT.txt --config config_sample.json --out-dir output_melt/
```

## How to Write config.json

Map channel names to roles. `standard` holds the quantity (in any unit: copies / mol / ng),
`sample` is a label, and `ntc` is a well expected to be undetected.

```json
{
  "channel_names": ["ch0","ch1","ch2","ch3","ch4","ch5","ch6","ch7"],
  "frac_baseline": 0.5,
  "roles": {
    "standard": {"ch0": 1000000, "ch1": 100000, "ch2": 10000,
                 "ch3": 1000, "ch4": 100, "ch5": 10},
    "sample":   {"ch6": "eDNA_sample_1", "ch7": "eDNA_sample_2"},
    "ntc": []
  }
}
```

## Design of eDNA Quantification (target region and standard)

As requested, prepare the **target region** as "an amplicon that is slightly broader than
the detection range" and use it as a standard in the same well every time. Given that
multiplexing is impossible with single-channel detection and that qPCR quantification relies
on "comparison of Ct values," design it as follows:

- **Standard amplicon (fixed well)**: stage-dilute an amplicon of known copy number of the
  target region (e.g. 10^6 → 10 copies). This yields a `log10(quantity) vs Ct` standard curve.
- **Target sample (any well)**: quantify the target region amplified from eDNA under the same
  conditions, converting back to "copies per reaction" by fitting its Ct onto the standard curve.
- **Meaning of "slightly broader range"**: by preparing an amplicon whose upper and lower limits
  slightly exceed the detection range (dynamic range), the dilution series reliably covers the
  detection range and avoids extrapolation error.

## Output

- `output/results.tsv` — PCR efficiency / R² / Ct per well / quantity (tab-separated)
- `output/report.md` — short report (Markdown)
- `output/amplification_curves.png` — normalized amplification curves (ΔRn, matplotlib)
- `output/standard_curve.png` — standard curve (with regression equation, efficiency, R², matplotlib)

If a melting (HRM) segment is present, the following are added:

- `output/results.tsv` / `report.md` — Tm per well in a `# melt (HRM)` section
- `output/melt_curves.csv` — long format (`temp, channel, label, f, neg_dfdt`)
- `output/melt_curves.png` — melting curve (F vs T) and -dF/dT (Tm peak), a two-panel figure

You can pass the file path directly to `--data` (e.g. `DATAQPCR.TXT` extracted straight from
the device; the filename need not be `DATA.TXT`). If you don't need graphs, use `--no-plots`
to skip matplotlib.

### Plot with R / ggplot2 (optional)

If you want to polish figures for publication with **ggplot2** instead of Python's plotting,
`run_qpcr.py` also outputs a structured CSV that is easy to read in R.

Generated CSVs:

- `amplification.csv` — long format (`cycle, channel, role, raw, normalized_rn`)
- `standard_curve.csv` — standard points (`channel, log10_quantity, ct`)〔only if the standard was regressed that run〕
- `calibration_meta.csv` — calibration metadata (slope/intercept/R²/efficiency)〔when using external calibration〕
- `samples.csv` — quantity (`label, channel, ct, copies`)

Plot with the corresponding R scripts:

```bash
# Amplification curves
Rscript scripts/plot_amplification.R output/sample_rtest/amplification.csv out.png "Oikawa cytb amplification curves"
# Standard curve (if the standard was regressed that run)
Rscript scripts/plot_standard_curve.R output/std_rtest/standard_curve.csv out.png
# Quantity comparison (dot plot + numeric labels, log10 Y axis)
Rscript scripts/plot_samples.R output/sample_rtest/samples.csv out.png
```

`ggplot2` and `scales` must be installed. Japanese titles render correctly if a font such as
Noto Sans CJK is installed on the system.

## Simple Quantification (only two unknown-sample wells collected)

A standard curve does **not** need to be run every time. As long as you don't change the
reaction conditions (enzyme, primers, temperature protocol), you can reuse a calibration you
already took. To quantify just two unknown-sample wells, proceed as follows:

### 1. Generate a calibration file (first time only)

Run `make_calibration.py` with a `DATA.TXT` containing a standard dilution series and its
role-specification config to generate a calibration file (`calibration_*.json`), then give it
a target name.

```bash
# Run with the dilution-series DATA.TXT and the standard role spec config
python3 scripts/make_calibration.py \
    --data data/DATA.TXT \
    --config config_std.json \
    --target "Oikawa cytb" \
    --out calibration_oikawa_cytb.json
```

The generated calibration file includes:

- The regression equation (`slope`, `intercept`), R², and PCR efficiency (`efficiency`)
- Target name, generation date, and Ct values for each standard well

### 2. Collect unknown samples

Put **unknown samples in only two of the eight wells**. The other six wells may be empty (or
contain water). For example: unknown samples in ch0, ch1; ch2–ch7 with no water.

### 3. File placement and configuration

Place the collected file under `data/` named **`DATA.TXT`. Then use `config_sample.json` —
ch0 and ch1 are the unknown samples (standard is optional).

```json
{
  "channel_names": ["ch0","ch1","ch2","ch3","ch4","ch5","ch6","ch7"],
  "frac_baseline": 0.5,
  "roles": {
    "sample": {"ch0": "unknown_1", "ch1": "unknown_2"},
    "standard": {},
    "ntc": []
  }
}
```

### 4. Run analysis (using external calibration)

Specify the generated calibration file with `--calibration`. This lets you quantify unknown
samples using a saved calibration without re-running the standard that time.

```bash
python3 scripts/run_qpcr.py \
    --data data/DATA.TXT \
    --config config_sample.json \
    --calibration calibration_oikawa_cytb.json \
    --out-dir output/sample_run/
# → results.tsv in output/sample_run/ gets the Ct and quantity (copy-number equivalent) for ch0, ch1
```

The generated `results.tsv` also records the calibration target name, calibration date,
regression equation, efficiency, and R².

### Notes

- A calibration file can be reused as many times as long as you don't change the conditions
  (enzyme, primers, temperature protocol).
- When you change reaction conditions (e.g. a new batch of enzyme or primers), re-take the
  calibration with `make_calibration.py`.
- If you omit `--calibration`, the script regresses that run's standard and quantifies — the
  traditional behavior.

## Dependencies

- Python 3.9+
- numpy, matplotlib (plotting only)
- scipy is not used (Savitzky-Golay smoothing is implemented from scratch)
